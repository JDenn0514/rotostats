## Problem

Category directionality (which scoring categories are "lower is better":
ERA, WHIP, FIP, xFIP, etc.) is currently siloed inside `sgp_denominators()`
as the `inverse_categories = c("ERA", "WHIP")` argument. Every other
consumer — `zaa()`, `zar()`, `pvm()`, `replacement_level()` — that needs
directionality would have to re-invent the same knowledge.

A user running a league that scores FIP instead of ERA, or OPS instead of
AVG, has no way to tell the package about that directionality without
passing the same override to every downstream function. Forgetting on one
call silently inverts the sign and corrupts results.

## Solution (Option 2 from the 2026-04-21 design discussion)

Three-layer resolution, consistent with the existing `scoring_categories`
pattern in the package:

```
explicit function arg   >   config$inverse_categories   >   package lookup
```

1. **Package lookup** — `INVERSE_CATEGORIES` constant + `inverse_categories()`
   exported accessor (mirrors the existing `rate_stat_denominators()` /
   `RATE_STAT_DENOMINATORS` pattern in `R/replacement_params.R`).

2. **`league_config()`** — new optional `inverse_categories` field.
   Users declare it once at config construction; downstream calls auto-inherit.

3. **Per-function override** — any consumer function that takes an
   `inverse_categories` arg uses **full replacement** semantics when the
   user passes it (matches `sgp_denominators()`'s current behavior).
   Absence of the arg → inherit from `config$inverse_categories` → fall
   back to the package lookup.

## Non-goals (out of scope for this plan)

- Refactoring `sgp()`'s ERA/WHIP/AVG hardcoding. That is
  `plans/sgp-advanced-rate-stats.md` — a separate plan. This plan touches
  `sgp_denominators()` only (which already has the `inverse_categories`
  argument).
- Adding support for new rate-stat *formulas* (FIP, OPS, K/9). Directionality
  and rate-formula identity are orthogonal concerns; formulas are Plan B.
- Building `zaa()`, `zar()`, `pvm()`. Those consume this infrastructure
  but are built in their own runs.

## API Decisions (committed)

### 1. Lookup shape

```r
# R/inverse-categories.R
INVERSE_CATEGORIES <- c(
  "ERA", "WHIP", "FIP", "xFIP", "SIERA", "xERA", "BB/9", "HR/9"
)

#' @export
inverse_categories <- function() INVERSE_CATEGORIES
```

A **character vector of category names** (the inverse ones), NOT a named
`c(ERA="lower", ...)` direction map. Rationale: matches the existing
`sgp_denominators()` arg shape (`if (cat %in% inverse_categories)`),
simpler to reason about, absence-means-not-inverse semantics are clear.

Starter contents include pitcher ratio stats where lower-is-better. Final
list TBD during implementation — at minimum: ERA, WHIP, FIP, xFIP, SIERA,
xERA, BB/9, HR/9. K/9, K%, K-BB% are **higher-is-better** for pitchers,
NOT in this list. Hitter K% is contextual; skip for now.

### 2. `league_config()` field

```r
league_config(
  n_teams       = 12L,
  roster_slots,
  pitcher_slots = 9L,
  categories,
  inverse_categories = NULL,   # <-- new
  league_type   = "mixed",
  budget        = 260L,
  budget_split  = 0.60,
  keeper        = FALSE
)
```

- `NULL` (default) → field stored as `NULL`; downstream functions fall
  through to the package lookup.
- Character vector → validated, uppercased, stored.
- Validation: every element must be in `config$categories` after uppercase
  normalization (same rule as `sgp_denominators()` applies). Violation
  aborts with `rotostats_error_invalid_inverse_categories`.
- `print.league_config()` prints the effective inverse list when non-NULL
  (or `"(none declared)"` when NULL).

### 3. `sgp_denominators()` default resolution

**Before:**

```r
sgp_denominators(..., inverse_categories = c("ERA", "WHIP"), ...)
```

**After:**

```r
sgp_denominators(..., inverse_categories = NULL, ...)
```

Resolution (inside the function body, first step after arg validation):

```
1. If user passed `inverse_categories` explicitly (not NULL):
   use it as-is (full replacement). Validate each name is in
   scoring_categories. No config consultation.
2. Else if config$inverse_categories is non-NULL:
   use config$inverse_categories.
3. Else:
   use intersect(scoring_categories, inverse_categories()).
   This preserves today's behavior — ERA/WHIP remain inverse by default
   when scored.
```

Emit a one-shot `cli_inform()` naming the effective inverse_categories
after resolution (as today).

### 4. Override semantics on functions: **full replacement**

Per the 2026-04-21 discussion: when a user explicitly passes
`inverse_categories` to a function, the set is replaced entirely, not
augmented. This matches `sgp_denominators()`'s existing behavior and
avoids the "did I forget ERA?" confusion in ad-hoc overrides. Document
this explicitly in roxygen and in `specs/spec-sgp.md`.

## Acceptance Criteria

1. `inverse_categories()` returns a character vector; callable and
   documented. `?inverse_categories` shows the starter list.
2. `league_config(..., inverse_categories = c("FIP", "WHIP"))` validates,
   uppercases, stores. `lg$inverse_categories` is readable.
3. `league_config(..., inverse_categories = c("FOO"))` aborts with
   `rotostats_error_invalid_inverse_categories` when `FOO` is not in
   `categories`.
4. `sgp_denominators()` with `inverse_categories = NULL` (new default)
   reproduces prior behavior when ERA/WHIP are scored: legacy tests pass
   unchanged.
5. `sgp_denominators()` inherits from `config$inverse_categories` when
   the user passes the config and leaves the arg NULL.
6. `sgp_denominators(..., inverse_categories = "FIP")` with a config that
   declares `c("ERA","WHIP")` uses `{FIP}` only (full replacement).
7. `print.league_config()` shows the effective inverse list.
8. `R CMD check` zero errors, zero warnings. All pre-existing testthat
   tests pass. New tests added for the three resolution paths.
9. No changes to `R/sgp.R`, `R/par.R`, `R/replacement.R`,
   `R/replacement-level.R`.

wires `sgp()` into the new infrastructure — not ideal but survivable.
