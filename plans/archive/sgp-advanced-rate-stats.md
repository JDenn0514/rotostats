## Problem

`sgp()` hardcodes rate-stat support to `c("ERA", "WHIP", "AVG")` and each
stat's specific blended-pool formula. A league that scores FIP, xFIP,
SIERA, xERA, K/9, BB/9, HR/9, or any non-ERA/WHIP pitcher rate stat will
have those categories silently dropped from `sgp_[cat]` output. The
failure is quiet — no `cli_warn()` flags the missing rate stat.

Grep of `R/sgp.R`:

```r
# Step 7
rate_cats   <- intersect(scored_cats, c("ERA", "WHIP", "AVG"))

# Step 10c (baselines)
avg_ERA  <- stats::weighted.mean(ts_base$ERA, ts_base$IP)
avg_WHIP <- stats::weighted.mean(ts_base$WHIP, ts_base$IP)
avg_AVG  <- stats::weighted.mean(ts_base$AVG, ts_base$AB)

# Step 11 (pool construction)
pool_ER <- sum(pool_pitchers$ERA * pool_pitchers$IP / 9, na.rm = TRUE)
pool_WH <- sum(pool_pitchers$WHIP * pool_pitchers$IP,    na.rm = TRUE)
pool_H  <- sum(pool_hitters$AVG  * pool_hitters$AB,      na.rm = TRUE)
```

Each stat's formula is branched by name. To add FIP a future maintainer
would copy-paste the ERA branch and modify the numerator expression.

## Solution

Introduce a **rate-stat formula registry**: `RATE_STAT_FORMULAS`
(internal constant) + `rate_stat_formulas()` (exported accessor), mirroring
`rate_stat_denominators()` / `RATE_STAT_DENOMINATORS` in
`R/replacement_params.R`.

Each registry entry describes a linear-pool rate stat in terms of:

1. **Denominator column** — `IP` for pitcher rates, `AB` for AVG-like,
   `PA` for OBP-like, etc.
2. **Numerator function** — given a player's rate value and denominator,
   return the numerator (e.g., `ER = ERA × IP / 9`). This is the extracted
   "how do I weight this rate to sum it up over a pool?" logic.
3. **Blended-pool formula** — given total numerator, total denominator,
   and optionally player additions, return the rate (e.g.,
   `ERA = (pool_ER + player_ER) × 9 / (pool_IP + player_IP)`).

For linear rate stats, items 2 and 3 collapse to the same pattern with a
multiplicative scale factor. The registry stores that pattern, not
function bodies for every entry.

## Non-goals (out of scope for this plan)

- **Directionality** — that's `plans/inverse-categories-infrastructure.md`.
  This plan does NOT edit `R/league-config.R`, `R/sgp-denominators.R`, or
  anything that touches `inverse_categories`.
- **Non-linear rate stats** — OPS, wOBA, xwOBA, BABIP, wRC+, etc. have
  formulas that are not expressible as "sum numerator, sum denominator,
  divide." Defer to a follow-up plan (`plans/sgp-compound-rate-stats.md`,
  not yet drafted). Supported rate stats after this plan: ERA, WHIP, AVG,
  FIP, xFIP, SIERA, xERA, K/9, BB/9, HR/9.
- **`sgp_denominators()` changes** — it already handles new rate stats
  via `inverse_categories` (directionality only). It does not compute
  blended-pool formulas; that's `sgp()`'s job. Plan A covers
  `sgp_denominators()` default resolution.
- Building `pvm()`, `zaa()`, `zar()`, `dollar_values()`.

## API Decisions (committed)

### 1. Registry shape (linear-pool stats only)

```r
# R/rate-stat-formulas.R
RATE_STAT_FORMULAS <- list(
  ERA  = list(denominator_col = "IP", scale = 9,  numerator_fn = function(rate, denom) rate * denom / 9),
  WHIP = list(denominator_col = "IP", scale = 1,  numerator_fn = function(rate, denom) rate * denom),
  AVG  = list(denominator_col = "AB", scale = 1,  numerator_fn = function(rate, denom) rate * denom),
  FIP  = list(denominator_col = "IP", scale = 1,  numerator_fn = function(rate, denom) rate * denom),
  xFIP = list(denominator_col = "IP", scale = 1,  numerator_fn = function(rate, denom) rate * denom),
  SIERA = list(denominator_col = "IP", scale = 1, numerator_fn = function(rate, denom) rate * denom),
  xERA  = list(denominator_col = "IP", scale = 1, numerator_fn = function(rate, denom) rate * denom),
  "K/9"  = list(denominator_col = "IP", scale = 9, numerator_fn = function(rate, denom) rate * denom / 9),
  "BB/9" = list(denominator_col = "IP", scale = 9, numerator_fn = function(rate, denom) rate * denom / 9),
  "HR/9" = list(denominator_col = "IP", scale = 9, numerator_fn = function(rate, denom) rate * denom / 9)
)

#' @export
rate_stat_formulas <- function() RATE_STAT_FORMULAS
```

Blended-pool formula (derived from registry entry `f`):

```
player_num  = f$numerator_fn(player_rate, player_denom)
pool_num    = sum(f$numerator_fn(pool$rate, pool$denom), na.rm = TRUE)
pool_denom  = sum(pool[[f$denominator_col]], na.rm = TRUE)
blended     = (pool_num + player_num) * f$scale / (pool_denom + player_denom)
```

### 2. `sgp()` behavior change when a rate stat is scored but not in the registry

Two cases:

- **Scored rate stat IS in registry**: proceed as today using registry entry.
- **Scored rate stat is NOT in registry and not overridable**: abort with
  `rotostats_error_unknown_rate_stat_formula`. (Distinct from
  `rotostats_error_unknown_rate_stat` which `replacement_level()` throws
  for missing denominators — different class so each thrower is
  unambiguous.)

This is a new error path. Before this plan, the category was silently
dropped. After this plan, the abort tells the user to either remove the
category from `config$categories` or extend the registry via the override
(next item).

### 3. User override

New argument on `sgp()`:

```r
sgp(..., rate_stat_formulas = NULL, ...)
```

- `NULL` (default) → use the package `RATE_STAT_FORMULAS`.
- Named list matching the registry shape → entries merged **on top of**
  the package default (augment semantics, NOT full replacement). Rationale:
  users extending with one custom rate stat should not have to
  re-declare ERA/WHIP/AVG. Note this is the OPPOSITE of `inverse_categories`
  override semantics (Plan A uses full replacement); document the
  asymmetry and explain the rationale in roxygen.

Validation: each override entry must be a list with names
`denominator_col` (character scalar), `scale` (numeric scalar),
`numerator_fn` (function of two numeric args, returns numeric). Violation
aborts with `rotostats_error_invalid_rate_stat_formula`.

### 4. Determining whether a scored category is a rate stat

Today: `rate_cats <- intersect(scored_cats, c("ERA", "WHIP", "AVG"))`.
After this plan: `rate_cats <- intersect(scored_cats, names(effective_registry))`
where `effective_registry = merge(RATE_STAT_FORMULAS, user_override)`.

Counting stats remain the complement: `count_cats <- setdiff(scored_cats, rate_cats)`.

### 5. What `projections` must contain

For each scored rate stat, `projections` must contain:
- The rate column itself (e.g., `FIP`).
- The denominator column from the registry entry (e.g., `IP` for FIP).

Missing the rate column → existing `rotostats_warning_missing_category_column`
fires (no change). Missing the denominator column → new abort with
`rotostats_error_missing_rate_denominator_column` naming the rate and
the missing column.

## Acceptance Criteria

1. `rate_stat_formulas()` returns a list; documented, exported.
2. Calling `sgp()` on a league scoring `c("R","HR","RBI","SB","AVG","W","K","SV","FIP","WHIP")`
   with matching `sgp_denominators()` output produces a valid `sgp_fip`
   column (numeric, no all-NA). Legacy ERA/WHIP/AVG leagues produce
   identical output to pre-change.
3. `sgp()` on a league scoring `K/9` with `K/9` present in projections
   and denominators computes `sgp_k_9` (or whatever the column-name
   convention dictates). If the existing column-name convention
   doesn't support `/`, this plan may need to introduce sanitized
   naming — flag as planner HOLD if so.
4. `sgp()` with a scored rate stat not in the registry and no override
   aborts with `rotostats_error_unknown_rate_stat_formula`.
5. User override: `sgp(..., rate_stat_formulas = list(MYSTAT = list(denominator_col="PA", scale=1, numerator_fn=function(r,d) r*d)))`
   works when `MYSTAT` and `PA` are both in projections.
6. `R CMD check` zero errors, zero warnings. All pre-existing testthat
   tests pass. New tests added for the registry path, user override,
   and the two new error classes.
7. No changes to `R/league-config.R`, `R/sgp-denominators.R`,
   `R/par.R`, `R/replacement*.R`.

## Non-Overlap with Plan A (inverse-categories-infrastructure)

Plan A edits `R/league-config.R` and `R/sgp-denominators.R` and the
`sgp_denominators()` section of `specs/spec-sgp.md`. This plan edits
`R/sgp.R` and the `sgp()` section of `specs/spec-sgp.md`. Both worktrees
will touch `specs/spec-sgp.md`, `NEWS.md`, and `plans/error-messages.md`;
those will merge cleanly as long as:

- Each plan restricts spec edits to its own section (header anchors).
- Each plan's `NEWS.md` entry is a **separate bullet** in the Unreleased
  section — never editing the same line.
- Each plan reserves distinct error class names:
  - Plan A uses the existing `rotostats_error_invalid_inverse_categories`
    (adds `league_config()` as a new thrower — not a new class).
  - Plan B introduces `rotostats_error_unknown_rate_stat_formula`,
    `rotostats_error_invalid_rate_stat_formula`, and
    `rotostats_error_missing_rate_denominator_column` — all fresh class
    names that Plan A does not touch.

### Recommended merge order

Plan A merges first. Plan B can adopt `config$inverse_categories`
inheritance in `sgp()` as a small follow-up after merge — NOT in this
plan. If Plan B lands first, Plan A's merge does not disturb Plan B's
new code path because `sgp()`'s directionality logic is inherited via
`sgp_denominators()` output signs (already present in `denominators`
attribute), not read directly from `config` in `sgp()` today.

Put another way: `sgp()` does NOT currently read `inverse_categories`
from anywhere. Plan A changes how `sgp_denominators()` computes its
output. Plan B changes how `sgp()` interprets `denominators` + rate-stat
formulas. The two are on perpendicular axes.

## Open Questions to Resolve in Planner HOLD

1. **Column-name convention for rate stats with slashes.** Current
   convention is `sgp_[tolower(cat)]`, which produces `sgp_k/9` for
   `K/9` — invalid column name. Options:
   - Strip non-alphanumerics: `sgp_k9`.
   - Substitute: `sgp_k_per_9`.
   - Reject slash-containing category names in `sgp()` with a clear
     abort.
   Planner should propose and get user sign-off.

2. **Whether `SIERA` and `xERA` should be in the starter registry or
   deferred.** Both use the ERA-like linear pool structure, so the
   registry entry is identical to ERA modulo name. Recommend include
   from day one — no incremental cost.

3. **Whether the override semantics should actually be full replacement**
   to match Plan A. The asymmetry (Plan A full replacement, Plan B
   augment) is deliberate in this draft but the user may prefer symmetry.
   Planner can raise as a HOLD question.

4. **Whether xFIP / SIERA / xERA should also have direction entries in
   `INVERSE_CATEGORIES` (Plan A's lookup).** Yes — they're all lower-is-
   better. Already listed in Plan A's starter contents. Cross-reference:
   Plan A adds these names to the directionality lookup; Plan B adds the
   same names to the rate-formula registry. Both are needed for an
   end-to-end FIP-league workflow.
