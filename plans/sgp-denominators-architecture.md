## 1. Direction-aware rank-flip for inverse categories

### What it is

`sgp_denominators()` uses a **rank-1=worst, rank-n=best** convention.  When the
OLS path fits `standings_position ~ category_total`, we need the slope to be
positive for normal categories (more HRs → better standing) and **negative** for
inverse categories (more ERA → worse standing).

### Why the flip is needed

`base::rank()` always assigns rank 1 to the *lowest* value.  For a normal
category like HR that is rank-1=worst, which is what we want.  For ERA a lower
value is *better*, so `rank(ERA)` would give the best pitcher rank 1 — the
*wrong* end of the scale — and produce a positive OLS slope, i.e., the
regression would say "as ERA increases, your standing improves", which is
backwards.

### Where it lives

```r
# R/sgp-denominators.R, inside the per-year loop in §5.11 Step 2
raw_rank <- rank(ts_y[[cat]], ties.method = "average")
standings_pos <- if (cat %in% INVERSE_CATEGORIES) {
  n_y + 1L - raw_rank      # flip: best ERA team gets rank n_y
} else {
  raw_rank
}
```

The same flip is duplicated in the bootstrap resampling path (the inner
`vapply` loop over `sample_years`).  If bootstrap is extended in the future,
keep both in sync.

### What `INVERSE_CATEGORIES` is

```r
INVERSE_CATEGORIES <- c("ERA", "WHIP")
```

Defined in `R/sgp-denominators-helpers.R`.  If your league scores additional
inverse categories (e.g., "OAVG" for opponent average, "BB9" for walks per
nine innings) you must add them to this constant.

### The sign-check warning

After computing the weighted-mean slope, the implementation checks:

- Inverse category with positive slope → `rotostats_warning_unexpected_slope_sign`
- Normal category with negative slope → `rotostats_warning_unexpected_slope_sign`

Under normal, correct data these warnings will never fire.  Seeing them in
production means the data is corrupted, a category is mislabelled, or the rank
source (`{CAT}_PTS` column) is using a different sign convention.

## 2. `as.double` / `as.numeric` dispatch on list S3 objects

### The problem

`as.numeric` is a base R *primitive*.  When called on a list-based S3 object,
the primitive intercepts the call before S3 dispatch reaches the generic, so the
method `as.numeric.sgp_denominators` is never invoked — `as.numeric(x)` silently
returns `numeric(0)` (empty vector) instead of the denominators.

Minimal reproducible example:

```r
as.numeric.my_class <- function(x, ...) "dispatched!"
x <- structure(list(), class = "my_class")
as.numeric(x)  # → numeric(0)  — dispatch swallowed by primitive
```

### The fix

Register the coercion as `as.double.sgp_denominators` instead.  `as.double`
*does* dispatch correctly for list objects.  `as.numeric(x)` also works because
R's internal `as.numeric` implementation delegates to `as.double` as part of its
fallback chain:

```r
as.double.sgp_denominators <- function(x, ...) x$denominators
```

NAMESPACE entry (generated by `devtools::document()`):
```
S3method(as.double,sgp_denominators)
```

### Lesson for future authors

**Any list-based S3 class in this package that needs a coercion to numeric
should register `as.double.<class>`, not `as.numeric.<class>`.**

The R version where this behaviour was confirmed: 4.5.2 (macOS aarch64).

## 3. OLS vs. SD estimand distinction

### The two methods target different quantities

| Method | Estimand | Typical value (n=12, σ=25) |
|--------|----------|---------------------------|
| `"ols"` | `1 / |β̂|` where `β̂` is the OLS slope of `rank ~ total` | ≈ 6.7 |
| `"sd"` | `σ × (n-1) / E[R_n]` | ≈ 82 |

The factor-of-12 difference is not a bug — they are answering *different*
questions.

- **OLS** asks: "given the slope of the rank-vs-total relationship in the data,
  how many category units move me one place?"  This reflects actual league
  history including the correlation structure.

- **SD** asks: "given that totals are approximately normal with standard
  deviation σ, how large is the expected gap between adjacent teams?"  The
  answer is `σ × (n-1) / E[R_n]`, where `E[R_n]` is the expected range of `n`
  standard normals.

### Why this matters

Do **not** mix methods across categories within the same valuation run.  Using
OLS denominators for counting stats and SD denominators for rate stats will
produce systematically wrong relative category weights.  If you switch to
`method = "sd"`, apply it to all categories.

### Source of confusion (sim-spec error)

The `sgp-denominators-2026-04-16` simulation spec (`sim-spec.md §2`) labelled
the SD formula as "the true denominator for DGP-A" and used it as the OLS
calibration target, producing an apparent 92% relative bias in the OLS
estimates.  The simulator correctly identified the inversion and used empirical
θ calibration instead.  The spec formula was **not** corrected in-place (a
future Planner action item); this note serves as the record until it is.

## 4. Bootstrap CI coverage caveat (Jensen's inequality)

The OLS denominator is `d = 1 / |β̂|`.  Because inversion is convex,
`E[1/|β̂|] > 1/E[|β̂|]` (Jensen's inequality), producing a small upward bias
of ≈ 1% at `n_years = 6`.  The **percentile bootstrap** CI is centred on the
biased estimate, so the lower bound lies above the true denominator too often.
Empirical coverage at `n_years = 6` is ≈ 84–85% at nominal 95%.

This is documented in `?sgp_denominators` under `@section Caveats` and in
`NEWS.md`.  A BCa bootstrap would correct it; that is a future enhancement.
